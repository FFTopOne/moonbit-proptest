# 项目说明（一页）

**项目名**：moonbit-proptest
**方向**：开发者工具 / 测试基础设施
**语言**：MoonBit（唯一实现语言，无其他语言依赖）

---

## 一句话

给 MoonBit 的整合式收缩属性测试库：生成器返回「值 + 收缩树」，失败时给出**可重放、已最小化**的反例，并支持基于模型的状态机测试。

## 要解决的真实问题

MoonBit 标准库已有 `core/quickcheck`，但它的生成器签名是 `(size, rng) -> T` —— **只产出值**，收缩交给独立的 `Shrink` trait 按类型完成。

这个结构有个硬上限：收缩时只看得到最终的 `T`，看不到它是怎么被生成的。后果在依赖式生成上最明显——先生成长度、再生成该长度的数组时，收缩改不动长度，只能删元素或把元素改小，要么停在原长度，要么产出生成器自己都不承认的畸形值。

这不是"再多写一层封装"能解决的，得换数据结构。

## 方案

生成器返回玫瑰树而非裸值：

```
Gen[T] :: (Int, Rng) -> Tree[T]?
Tree[T] :: { value : T, kids : () -> Array[Tree[T]] }
```

三个关键机制：

1. **整合式收缩**。`flat_map` 在收缩外层值时**重新派生**内层生成器（随机流冻结保证可复现），于是"决定形状的上游值"和"下游内容"一起收缩，且永远满足生成器自身的约束。
2. **可重放的失败**。记录 `case_seed` + `size` + 收缩路径，`replay` 从零重算出同一个反例。存派生结果而非配置，所以别人调整 `count` / `max_size` 之后旧反例依然有效。
3. **三态结果**。生成器可以主动拒绝（`None`），跑器计为 discard；一轮一个有效样本都没有时返回 `GaveUp` 而不是 `Passed` —— 没判断过的运行不能报绿。

在 `flat_map` 之上，状态机测试几乎零成本：命令序列用 `flat_map` 链式派生，删除任意一条命令后，其后命令依新模型状态重新生成，序列始终内部自洽。这是"把 `flat_map` 做对"的直接回报。

## 与已有工作的关系

不重复造 `core/quickcheck`：那是按类型收缩的通用方案，本项目补的是它架构上够不到的部分（整合式收缩、路径重放、discard 语义、状态机）。两者的差异在 README 有逐项对照表，`docs/DESIGN.md` 记录了取舍理由。

RNG 的混合函数使用 SplitMix / MurmurHash3 的公开算法，并以 SplitMix 公布的参考向量做交叉验证。
