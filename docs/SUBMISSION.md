## 二、申报书骨架（8 项，一页以内）

表里列出的必写项，按顺序。每项下面是我能给的事实素材，**文字你来写**。

### 1. 项目名称

`moonbit-proptest`（可加一句副标题：给 MoonBit 的整合式收缩属性测试库）

### 2. 项目简介

要点：解决什么问题、给谁用、和现有方案的区别。

可用事实：
- MoonBit 标准库已有 `core/quickcheck`，其生成器签名是 `(size, rng) -> T`，只产出值，收缩由独立的 `Shrink` trait 按类型完成。
- 后果：依赖式生成（先生成长度、再生成该长度的数组）收缩时改不动长度。
- 本项目让生成器返回玫瑰树（值 + 收缩树），`flat_map` 收缩外层值时重新派生内层生成器，于是上下游一起收缩。
- 面向：写 MoonBit 库/工具/解析器的人，以及需要在 CI 里做回归的团队。

### 3. 项目方向，通用性说明

方向填：**开发者工具 / 测试基础设施（基础软件）**。

通用性要讲清楚（这是这一项的重点，不能只写"给某个项目用"）：
- 不绑定任何具体业务：任何 MoonBit 包都能用，只要它能被描述成"输入 → 输出"就能写成属性。
- 7 个包分层单向依赖（`rng → tree → gen → shrink → prop`，上层 `stateful` / `examples`），可分别复用：只要树的可以只用 `tree`，只要跑器的可以只用 `prop`。
- `stateful` 能直接测标准库自身的容器（`HashMap` / `Queue` / `SortedMap`），不限于本项目。
- `Replay` 的承载格式（种子 + size + 收缩路径）可以进 CI，与具体项目无关。

### 4. 至少 3 个完整的预期使用场景

**这一项现在完全空着，必须补，而且要"完整"**——写清谁在什么情况下用、解决什么、怎么用。

可展开的候选（挑 3 个写实）：

1. **库作者给容器写模型测试。** 给 `Queue` / `SortedMap` 这类容器定义命令（push/pop/lookup）与模型状态，用 `stateful.Machine` 生成命令序列，与真实实现逐步比对。出问题时得到的是最短失败序列——实测把一个 10 条命令的随机序列压到 3 条。
2. **线上失败固化成回归用例。** 报告里有 `seed` + `size` + `path`，把这三个值写进测试即可在任何机器上重算出同一个反例，不依赖保存的 fixture；改了生成器导致路径失效时 `replay` 返回 `None` 而不是给一个假值。
3. **解析器/协议实现的 round-trip 与对抗输入。** 用 `string()` / `array_of` 生成结构随机的输入，验证 `decode(encode(x)) == x`；失败时自动缩到最小反例（本项目自带的演示就是从随机数组缩到 `[1, 0]`）。
4. **团队培训与代码评审。** 把一个 40 元素的失败压成 2 元素，让评审者直接看到"哪个假设不成立"，比贴一大段日志有效。

### 5. 拟实现的核心功能

可直接对应现有 API（已实现，不是计划）：
- 生成器与组合子：`map` / `flat_map` / `filter` / `zip_with` / `one_of` / `frequency` / `array_of` / `option_of` / `result_of`
- 整合式收缩：玫瑰树 + 贪心搜索，`max_steps` / `max_attempts` 双预算
- 三态结果：`Passed` / `Falsified` / `GaveUp`；生成器可主动拒绝（`None` = discard）
- 可重放失败：`seed` + `size` + `path`
- 状态机测试：命令序列生成 + 三类序列收缩（任意位置删除 / 砍半 / 原地简化），靠 `precondition` 保证删除后仍合法
- 自带缺陷演示：3 个单行 mutant + 2 个状态机缺陷，断言精确到最小反例

数据：84 个测试、0 编译警告、7 个包、约 2755 行 MoonBit、零外部依赖。

### 6. 是否为原创项目、移植项目或参考已有开源项目

**原创项目，设计上参考了已有工作**——建议就照这个口径写，不要含糊：
- 接口形态参考 `moonbitlang/core/quickcheck` 的 `check` / `Generator`，但数据结构和收缩机制不同（它按类型收缩，本项目在生成时就地建收缩树）。
- 整合式收缩的思路来自 Haskell 的 Hedgehog 与 Python 的 Hypothesis，属于公开的算法思想，代码为独立实现。
- RNG 用 SplitMix / MurmurHash3 的公开算法，并以 SplitMix 公布的参考向量（`mkSMGen 1337`）做过交叉验证。

**写清这层关系比含糊更安全**：评审最可能质疑的就是"是不是把 `core/quickcheck` 重写了一遍"，主动对照反而显得可信。

### 7. 如为移植项目，需说明参考项目名称、来源链接和许可证

不是移植项目，这一项可写「非移植项目」。上面第 6 项已经交代了参考来源，够用。

如果想把参考关系写完整，可以附：`moonbitlang/core`（Apache-2.0）、Hedgehog（BSD-3）、Hypothesis（MPL-2.0），本项目自身 Apache-2.0。
