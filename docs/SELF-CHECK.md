## 二、评分维度（四项 × 25 分）

### 01 工程深度与实现强度

**认为可以到「优秀」。**

- 核心流程端到端可跑通：生成 → 收缩 → 报告 → 重放，全部有测试覆盖。
- 关键场景已验证：依赖式生成收缩（`flat_map`）、序列收缩（状态机）、拒绝语义（`filter` / `GaveUp`）、路径失效（`replay` 返回 `None`）。
- 范围交代清楚：`README` 末尾「已知边界」列了 5 条，包括"局部最小而非全局最小""`filter` 可能丢失收缩空间"这类会被追问的点，不回避。

- **覆盖率**：`moon coverage analyze` 后仍有 25 行未覆盖，集中在 5 个文件。逐条看下来是三类：变异体内部只有 3 个元素以上才走到的分支、可执行入口 `main`、以及需要两条管线同时拒绝才能触发的 `discard` 组合。第一轮是 55 行未覆盖、7 个文件，补了 27 个边界测试（`Gen::reject`、`zip`、`resize`、`scale`、`result_of`、`int`、`bool`、`GaveUp` 的放弃上限分支等）之后降到这个数。

### 02 技术贡献与攻关

**认为可以到「优秀」。**

实质难点有三个，都在代码里有对应设计而非事后解释：

1. **依赖式收缩**。`flat_map` 收缩外层值时重新派生内层生成器，随机流用 `inner_seed` 冻结保证可复现。这是按类型收缩架构上做不到的事，`docs/DESIGN.md` §2 有机制说明。
2. **惰性与正确性的张力**。收缩树必须惰性（否则爆炸），但惰性会掩盖 bug。用计数器测试把"不遍历就不构造"钉死（§3）。
3. **重放的边界**。存派生结果而非配置，使反例与 `count` / `max_size` 解耦；路径失效时返回 `None` 而非伪造值（§6）。

**取舍有记录**：`docs/DESIGN.md` §8 列了四个被放弃的方案及原因（memo 化、全局最小、`Outcome` 携带 `Error`、覆盖率引导模糊测试）。放弃 `Error` 那一条是真跑过、真踩过类型推断问题才改的。

### 03 生态增量

**这是最需要自我审视的一项。** 基线不是"没有"——`core/quickcheck` 已经存在，所以"缺少外部基线"这条风险必须正面处理。

对照结论（README 有完整表）：

- `core/quickcheck` 走的是**按类型收缩**路线：`Generator[T] -> T` + 独立 `Shrink` trait。
- 本项目走**整合式收缩**路线：`Generator[T] -> Tree[T]`。
- 差异不在功能多少，而在**能力边界**：依赖式生成（`flat_map`）的收缩、收缩路径重放、生成器主动拒绝，这三件事在按类型架构里表达不出来，不是没实现。

可复用的具体增量：

- `stateful` 可用来测标准库自身的 `HashMap` / `Queue` / `SortedMap` —— 这类容器正是模型测试的典型对象。
- `replay` 的种子+路径格式可以直接进 CI：把线上抓到的失败 seed 写成回归用例。
- `Tree` 与 `shrink` 是通用的：任何"从大输入压到小输入"的搜索（模糊测试最小化、配置化简）都能复用。

**未证明的部分**：没有真实第三方项目采用数据，"生态增量"目前是设计论证而非采用事实。如果时间允许，给 `moonbitlang/core` 提交一个用状态机测容器的用例会是最有力的补强。

### 04 开发与验证能力

**这一项应该是最强的，因为项目本身就是验证工具。**

- **84 个测试 / 0 警告 / `moon check -d` 通过**（CI 里两条都把警告当错误）。
- **对拍**：RNG 混合函数对标 SplitMix 公布的 `mkSMGen 1337` 参考向量；`mix64(1)` 的期望值用 Python 独立实现算出后写入断言，不是从自己的输出反抄。
- **变异测试思路**：`examples` 三个单行 mutant，每个断言**精确**最小反例（`[1, 0]` / `[0]` / `" "`），不是"非空"这种弱断言。
- **对照组**：换回正确实现后同一属性必须通过。没有这条，失败可能来自属性写错，整个演示就不成立。
- **反向测试**：谓词不可满足 → `GaveUp`；路径失效 → `None`；全 discard → 不能 `Passed`。这些是"工具本身出错"的防线。
- **性能红线**：树的惰性由计数器测试保证。
- **抽象失效的实证**：状态机第一版用 `flat_map` 串命令，演示跑出 `steps=0`——命令是叶子，序列树退化成叶子，一条命令都删不掉。这是工具自己的演示暴露了设计缺陷，而不是等评委发现。修法与推理在 `docs/DESIGN.md` §7。

**残项**：没有基准测试（生成/收缩吞吐未量化）；没有变异测试的自动化（mutant 是手写的三个，不是工具批量生成的）。

**一个真实收获**：覆盖率扫出来的未覆盖项里有 `Gen::reject` 这类"写了但从没被调用过"的公开 API，也有 `flat_map` 的拒绝传播分支——后者是文档里写明的行为，却没有任何测试钉住。这类"文档承诺 vs 实际验证"的缺口，靠读代码是发现不了的。
